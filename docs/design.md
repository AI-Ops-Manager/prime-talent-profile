# デザインの方針

目指しているのは、読みやすい一枚の書類。コンサルティングファームに提出する職務経歴書の落ち着き（白い紙、黒い文字、装飾を置かない）を保ちつつ、
読者が迷わず読めることを最優先にする。本文は大きめ、区切りは面と細い罫線、飾りのための要素は入れない。

## 既定のテーマ letterhead（ブランド色は2箇所だけ）

色は「この会社の書類だ」と分かる最小限にとどめる。

1. 紙の上端の細い色帯（1.6mm）
2. 「解決できる課題」「推薦理由」の箇条書きの点

それ以外はすべて黒とグレー。肩書きも「稼働可能」のタグも黒、節見出しは太い下線、基本情報は上下の細い罫線で区切った表、
「解決できる課題」は薄い灰色の面、課題に合う実績は黒地に白抜きの「適合」ラベル（汎用は「注目」）、最終ページの案内は黒の面に白文字。
角丸は 0.6〜1mm まで。影・グラデーション・英字の飾りラベル・セリフ体は使わない。

ほかのテーマ（`brand.json` の `theme`）: `panel`＝ブランド色の面を使う営業資料寄り、`classic`＝面は灰色で色は見出しの印だけ、
`rule`＝面を使わず罫線だけ、`mono`＝黒一色。骨格と文字サイズはどれも同じで、`template/themes/<名前>.css` が基本CSSに足される。

## 書体と基準値

| 要素 | 値 |
|---|---|
| 紙 | A4、上13mm・左右16mm・下16mm |
| 和文 | ヒラギノ角ゴシック（Mac）。無ければ Noto Sans JP（Google Fonts）、Noto Sans CJK JP |
| 欧文（イニシャル・年号・ページ番号） | Helvetica Neue / Arial |
| 本文（概要） | 11.5pt、行送り 1.85 |
| 本文（経歴・プロジェクト・推薦理由） | 11pt、行送り 1.7〜1.75 |
| 見出し（節） | 14pt 太字 |
| 氏名（イニシャル） | 30pt 太字 |
| 肩書き | 13.5pt 太字 |
| 基本情報 | 値 12.5pt 太字、ラベル 9pt |
| タグ | 10pt |
| 注記・ヘッダー・フッター | 8〜9.5pt |

この値は読みやすさの下限として決めている。分量が多いときにここを下げない。

## ページ構成と分量の目安

汎用版（`fit` / `points` なし）:

| ページ | 収まる量 |
|---|---|
| 1 | 氏名ブロック、基本情報、概要 2段落（各3〜4行）、対応領域 3行 |
| 2 | 経歴 3〜4件（本文各3行以内）、スキル 4行 |
| 3 | 実績 3〜5件（適合/注目の2件は3行、他は2行）、案内 |

提案型（`fit` / `points` あり）。2ページ目の先頭で「解決できる課題→推薦理由」を読ませる。
1ページ目に詰め込むと本文を小さくするしかなく、読みにくくなるため。1ページ目は概要を1段落にしてスキルまで、
対応領域は3ページ目の先頭に回す。

| ページ | 収まる量 |
|---|---|
| 1 | 氏名ブロック、基本情報、概要 1段落（3〜4行）、スキル 4行 |
| 2 | 解決できる課題 3点（各1行）、推薦理由 4点（各1〜2行）、経歴 3件（本文各2〜3行） |
| 3 | 対応領域 3行、実績 3件（適合の2件は3行、他は2行）、案内 |

## 溢れたときの直し方（この順で）

1. 本文の言い回しを削る。経歴は「何を、どこからどこまで担ったか」の2文に
2. 件数を減らす。経歴は直近3件、実績はラベル付き2件＋1件でも成立する
3. それでも入らなければ `talent.json` の `layout.pages` で4ページに割る

`npm run render` が「ページ N が X.Xmm はみ出しています」と出したら、上の順で直してもう一度描く。フォント・余白は触らない。

## 元にした資料からの変更点

パートナーの一社が先に作っていた版（クリーム地・白い角丸カード・オレンジのピル）を出発点に、項目はそのまま残して体裁を変えた。

| 項目 | 元 | このキット |
|---|---|---|
| 地と面 | クリーム地に白い角丸カード | 白い紙。面は基本情報・課題・案内の3箇所だけ |
| 稼働可能・契約形態 | 塗りのピル | 角1mmの枠線のタグ |
| 節見出し | 太字の英字＋オレンジの下線 | 日本語の見出し＋太い黒の下線 |
| 対応領域・スキル | 白いピル、スキルは角丸カード | 角1mmのタグを「ラベル｜タグ」の行に並べる |
| 実績（プロジェクト） | 角丸カード、代表は淡色の塗り | 見出しは「実績」。横罫線で区切り、課題に合うものは黒地の「適合」ラベル（汎用の資料では「注目」） |
| 課題・推薦理由 | 「こんな課題をお持ちの企業様に」「おすすめポイント」。呼びかけ調 | 「解決できる課題」「推薦理由」。客観の文。1ページ目ではなく2ページ目の先頭 |
| 案内 | ブランド色の面にロゴ | 黒の面に名義と会社名の文字（ロゴは色が合わないことがあるため） |
| ヘッダー | 日付｜文書種別 ／ タイトル ／ 名義 | ロゴ（または名義）／ タイトル｜発行年月。2ページ目以降はイニシャル｜肩書き |

## 色の扱い

- キーカラーが明るい（黄・ライム・水色など）と、白地に文字として置いたときに読めない。スクリプトがコントラスト比 4.5 を下回る色を文字用に自動で暗くする（`accentText`）。見出しの印と罫線には元の色をそのまま使う
- 文字色・罫線色を変えたいときだけ `brand.json` の `colors.ink / body / muted / hairline` を指定する。多くの会社はキーカラー1色で足りる
- 紙の色（`paper`）は白のままを推奨する

## 書き方

- 断定調。ビックリマーク・絵文字は使わない
- 実績の数字はデータベースの記載どおり。四捨五入や「約」の追加もしない
- 「〜を実現」「一気通貫」「シームレス」のような言葉は範囲や動詞に置き換える（「要件定義から引き継ぎまで」「作れる」「減る」）
- 見出しは名詞句。本文は「何を担い、何が変わったか」を数字で

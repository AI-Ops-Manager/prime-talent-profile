# デザインの方針

目指しているのは、コンサルティングファームに提出する職務経歴書の体裁。
白い紙、細い罫線、黒に近い文字。読み手が値踏みする資料なので、装飾で印象を作らず、
情報の並びと余白で読ませる。

ブランド色は「この会社が出している資料だ」と分かる最小限にとどめる。使う場所は次の6つだけ。

1. 節見出しの英字ラベル（OVERVIEW 等）と、その下の短い罫線（14mm）
2. 稼働状況のタグ（「稼働可能」の枠線と文字）
3. 肩書き（Corporate Ops / AI Automation Lead のような一行）
4. 代表プロジェクトの左罫線と、課題ブロックの左罫線
5. 課題・おすすめポイントの箇条書きの点（1.7mm の四角）
6. 最終ページの案内ブロックの上罫線

面を塗るのは、写真が無いときのイニシャル枠（キーカラーの淡色）だけ。
角丸はタグの 0.6mm と写真の 0.8mm 以外に使わない。影は使わない。

## 元にした資料からの変更点

パートナーの一社が先に作っていた版（クリーム地・白い角丸カード・オレンジのピル）を出発点に、項目はそのまま残して体裁を変えた。

| 項目 | 元 | このキット |
|---|---|---|
| 地と面 | クリーム地に白い角丸カード | 白い紙一枚。面差を作らない |
| 基本情報6項目 | 角丸の白カード | 上に太めの罫線、下に細い罫線を引いた表 |
| 稼働可能・契約形態 | 塗りのピル | 細い枠線のタグ（角丸 0.6mm） |
| 氏名（イニシャル） | 太いサンセリフ | セリフ体（EB Garamond）。年号・ページ番号も同じ書体 |
| 節見出し | 太字サンセリフの英字＋オレンジの下線 | セリフ体の英字ラベル（字間広め）＋黒の細い罫線＋キーカラーの短い罫線 |
| 対応領域・スキル | 白いピル | 枠線のタグ |
| プロジェクト | 角丸カード、代表は淡色の塗り | 罫線で区切った項目。代表は左罫線 |
| 課題・おすすめポイント（エンド訴求型） | 淡色の角丸カードに丸い点、太字多め | 課題は枠線＋左罫線のブロック、ポイントは四角い点の箇条書き。太字は1項目1箇所 |
| 案内（CTA） | キーカラー全面塗りのカード | 上罫線だけのブロック。ロゴまたは名義を右に |
| ヘッダー | 日付｜文書種別 ／ タイトル ／ 名義 | ロゴ（または名義）／ タイトル ／ 文書種別｜発行年月。2ページ目以降は右側がイニシャル｜肩書き |
| フッター | 名義 ／ Strictly Confidential 01 / 03 | 同じ |

## 基準値

| 要素 | 値 |
|---|---|
| 紙 | A4、上14mm・左右18mm・下17mm |
| 本文（概要） | 11pt、行送り 1.9 |
| 本文（経歴・プロジェクト） | 10.5pt、行送り 1.8 |
| 見出し（節） | 12pt 太字。英字ラベル 8.5pt |
| 氏名 | 30pt セリフ |
| 基本情報の値 | 12pt 太字。ラベル 8pt |
| タグ | 9pt |
| 注記・フッター | 7.5〜8.5pt |
| 本文フォント | Noto Sans JP（Google Fonts）。無ければ Hiragino Sans、Noto Sans CJK JP |
| 欧文セリフ | EB Garamond。無ければ Hiragino Mincho ProN、Georgia |

この値は読みやすさの下限として決めている。分量が多いときにここを下げない。

## 分量の目安

汎用版（打診先が決まっていない。対応領域が1ページ目）:

| ページ | 収まる量 |
|---|---|
| 1 | 概要 2段落（各3〜4行）、対応領域 3行（タグは1行に4つまで） |
| 2 | 経歴 3〜4件（本文各3行以内）、スキル 4グループ（各1行） |
| 3 | プロジェクト 3〜5件（代表2件は3行、他は2行）、案内ブロック |

エンド訴求型（`fit` / `points` あり。1ページ目を売り込みに使う）:

| ページ | 収まる量 |
|---|---|
| 1 | 概要 1段落（3〜4行）、課題 3点（各1行・全角30字以内）、おすすめポイント 4点（各1〜2行・全角50字目安） |
| 2 | 対応領域 3行、経歴 3件（本文各3行以内）、スキル 4グループ |
| 3 | プロジェクト 3〜5件、案内ブロック |

## 溢れたときの直し方（この順で）

1. 本文の言い回しを削る。経歴は「何を、どこからどこまで担ったか」の2文に
2. 件数を減らす。経歴は直近3件、プロジェクトは代表2件＋1件でも成立する
3. それでも入らなければ `talent.json` の `layout.pages` で4ページに割る

`npm run render` が「ページ N が X.Xmm はみ出しています」と出したら、上の順で直してもう一度描く。

## 色の扱い

- キーカラーが明るい（黄・ライム・水色など）と、白地に文字として置いたときに読めない。スクリプトがコントラスト比 4.5 を下回る色を文字用に自動で暗くする（`accentText`）。罫線と枠には元の色をそのまま使う
- 文字色・罫線色を変えたいときだけ `brand.json` の `colors.ink / body / muted / hairline` を指定する。多くの会社はキーカラー1色で足りる
- 紙の色（`paper`）は白のままを推奨する。色を付けると印刷時に面の境界が出る

## 書き方

- 断定調。ビックリマーク・絵文字は使わない
- 実績の数字はデータベースの記載どおり。四捨五入や「約」の追加もしない
- 「〜を実現」「一気通貫」「シームレス」のような言葉は範囲や動詞に置き換える（「要件定義から引き継ぎまで」「作れる」「減る」）
- 見出しは名詞句。本文は「何を担い、何が変わったか」を数字で

# ブラインドの線引き

ブラインド版の目的は「関心を持ってもらってから実名を開示する」こと。読み手が本人を特定できる情報は入れない。
一方で、経歴の説得力は残す。この2つの間に線を引く。

## 伏せるもの

- 氏名（イニシャル表記のみ）、生年月日、連絡先、SNS のアカウント、ポートフォリオの URL、本人の面談予約リンク（MCP の `schedulingUrl`）
- **現職・自社の社名。** 登記や検索で本人にたどり着ける。「IPO準備企業」「マーケティング支援会社（社名はご面談時に開示）」と業種で書く
- 代表取締役・役員・共同創業者の場合は、公開 URL のあるプロダクト名も伏せる（プロダクトから会社、会社から本人に届く）
- 登壇歴・受賞歴で本人が特定できるもの
- 写真は名義のルールに従う（`brand.json` の `defaults.hidePhoto`）。伏せる運用のときはイニシャルの枠になる

## 残してよいもの

- 過去に在籍した大手企業・有名サービスの実名。説得力の源泉なので削らない
  （ただし、本人から「過去在籍企業は避けたい」と申し出があれば伏せる）
- 実績の数字（件数・金額・削減率）。データの記載どおりに
- 学歴のうち、大学名程度（大学院の研究室名までは書かない）

## 正直なポジショニング

- `devSkillLevel` が none / vibecoding / junior の人を「シニアエンジニア」「スクラッチ開発」と書かない。
  「業務を知る人間が自分で作り、現場に定着させる」のような、実態に合う表現にする
- `aiSkillLevel` が tool_user / prompt_engineer の人に「AIエージェント開発」を名乗らせない
- 「統括した」「推進した」を「構築した」に書き換えない。データの動詞をそのまま使う
- 稼働の数字が出典で食い違うときは、保守的な方か幅で書き、`_note` に残す

## 書き方

- 断定調。ビックリマーク・絵文字なし
- 「〜を実現」「一気通貫」「シームレス」は範囲や動詞に置き換える
- 実績を並べるとき、同じ文型を3つ続けない
- 概要の太字は1段落に1箇所

## 案件ごとの上書き

依頼者の指示（「過去の在籍企業も伏せて」「単価は出さないで」）は、このファイルより優先する。
上書きした内容は `talent.json` の `_note` に書いて、次に作る人が分かるようにする。
